## ワークフロー全体図

```
/plan "タイトル"         ← 最初に必ず実行（全メディア共通）
        │
        ├── Udemy ─────────────────────────────────────────
        │   /structure → /toc → /script [S][L]
        │                     → /script-all（一括）
        │                           ↓
        │              /slides [S][L] → /slides-all
        │
        ├── 書籍 ──────────────────────────────────────────
        │   /book-structure → /book-toc → /book-chapter [N]
        │                              → /book-all（一括）
        │                                    ↓
        │                           /book-figures [N] → /book-embed [N]
        │                                    ↓
        │                           /book-format [形式] [A4|A5]
        │
        └── YouTube ────────────────────────────────────────
            /yt-structure → /yt-list [N] → /yt-script [N]
                                        → /yt-all [N]（一括）
                                               ↓
                                  /yt-slides [N] → /yt-slides-all
                                  /yt-visuals [N]

/check              ← 迷ったらまずこれ
/export [メディア]  ← 完成物を1ファイルに書き出し
```

## ① 企画フェーズ（全メディア共通）

```
/plan "業務改革を牽引するリーダーを目指す人のための生成AI活用実践講座"
```

Claude が以下を確認してくる（未指定の場合のみ）:
- 制作するメディア（Udemy / 書籍 / YouTube / すべて）
- ターゲット受講者のレベル
- コンテンツの性質
- 各メディアのボリューム目標

**生成ファイル**:
```
projects/{slug}/00_planning/
├── concept.md          ← 講座コンセプト・ゴール・差別化ポイント
└── target_audience.md  ← ターゲット分析・よくある誤解
```

> **確認ポイント**: ゴールが「〜できる」という動詞で終わる行動目標になっているか確認してください。

## ② Udemy講座の作り方

### /structure — セクション・レクチャー構成

```
/structure
```

Section 00「コース概要・はじめに」が自動的に先頭に追加されます。統計サマリーが表示されます。

### /toc — 詳細目次

```
/toc
```

各レクチャーの概要・推定時間・Udemyプレビュー設定を展開します。
**Udemy要件チェック**（総時間5時間以上など）が自動表示されます。

### /script — スクリプト生成

```
/script 1 2      # Section 01, Lecture 02 を生成
/script-all      # 全レクチャーを一括生成
```

**品質の基準（重要）**:
「ファイル全体の文字数」ではなく**会話文（鍵かっこ内）の文字数**で判断します。

| 種類 | 会話文目標 | 推定時間 |
|-----|---------|---------|
| 講義型 | 1,600〜2,000字 | 8〜10分 |
| ハンズオン型 | 1,800〜2,400字 | 10〜13分 |

各トピックは「概念定義 → 具体例・比喩 → 重要性」の3段階で説明されます。

### /slides — スライド生成（.pptx）

```
/slides 1 2      # Section 01, Lecture 02 のスライドを生成
/slides-all      # 全スライドを一括生成
```

スクリプト内の `[→ Slide XX]` 指示を参照してスライドを作成します。
スクリプトとスライドの対応マップ（`lecture_XX_map.md`）も同時生成されます。

## ③ 書籍原稿の作り方

### /book-structure — 章立て構成

```
/book-structure
```

「はじめに → 基礎 → 応用 → 実践 → まとめ」の5部構成を基本に設計します。

### /book-toc — 詳細目次

```
/book-toc
```

節ごとのカバートピック・図解挿入位置・コラムの場所も設計されます。

### /book-chapter — 章本文執筆

```
/book-chapter 3  # 第3章を執筆
/book-chapter 0  # 「はじめに」を執筆
/book-all        # 全章を一括執筆
```

原稿内に拡張フォーマットの図マーカーが自動挿入されます:
```
[図2.3: Dockerのアーキテクチャ | 種類: 概念図 | 内容: 3層構造の説明 | 自動生成: 可]
```

### /book-figures — 図の処理

```
/book-figures    # 全章の図を処理
/book-figures 3  # 第3章の図だけを処理
```

| 種類 | 処理内容 |
|-----|--------|
| 概念図・フロー・構造図・比較 | SVGファイルを自動生成 |
| スクリーンショット | 撮影手順書を生成 |
| イラスト | 7ツール対応のAI画像生成プロンプトを生成 |

**対応AIツール（イラスト）**:

| # | ツール | 特徴 |
|---|------|------|
| ① | ChatGPT Images 2.0 | 推奨・日本語OK・会話で修正可 |
| ② | DALL-E 3 | 英語で高精度 |
| ③ | Gemini（Nano Banana 2） | 日本語OK・Google連携 |
| ④ | Midjourney | 芸術的品質 |
| ⑤ | Stable Diffusion | ローカル・無料 |
| ⑥ | Adobe Firefly / Canva AI | 商用利用安全 |
| ⑦ | Imagen 2 / 3（Vertex AI） | API・大量生成向け |

### /book-format — 飾り付き原稿への変換

```
/book-format                 # 全形式（md・html・pdf）を A5 で出力
/book-format pdf A4          # PDF のみ A4 で出力
/book-format all A5 author="山田太郎"
/book-format docx A4         # Word（.docx）のみ A4
/book-format html 2          # 第2章だけ HTML で出力
```

| 引数 | 値 | 省略時 |
|-----|---|-------|
| 形式 | `md` / `html` / `pdf` / `docx`（Word） / `all` | `all` |
| 用紙サイズ | `A4` / `A5` | `A5` |
| 章番号 | `3` / `1,3` / `0-2` | 全章 |

表紙・目次・章扉・囲み記事（ポイント/注意など）・コード装飾を付けて `book/07_publish/{A4|A5}/` に出力します。
HTML/PDF のデザインは `format-template/`（A4: `techbook-a4.html` + `style-a4.css` / A5: `techbook-a5.html` + `style-a5.css`）です。
表紙の書名・シリーズ名・特長・著者などは `book/book_info.md` に、章扉のタグ・英字ラベルは章見出し直後の `# TAGS:` `# EN-TITLE:` に書きます（記法の全体: `references/book-markup.md`）。
`book/06_final/`（`/book-embed` の出力）があれば優先して使い、無い章は `03_manuscripts/` から変換します。

**変換のルール**（原稿の文章は変更しません）:
- 変換後に「原稿の全行が出力に含まれているか」を自動チェックし、欠けがあればエラーで知らせます。
- 段落・見出しの構造だけを整理します（折り返された段落の結合、6文を超える段落の分割、見出しレベルの補正）。整理した件数は `publish_report.md` に出ます。
- 引用ブロックは、先頭の `**ポイント**:` `**WARNING:**` `NOTE:` などのラベルで種別（POINT / TIP / NOTE / WARNING / DANGER / COLUMN）を決めます。ラベルのない引用は内容から推測せず、通常の引用のままです。
- 日付・著者は `date="..."` `author="..."` を指定したときだけ表紙に出します。

**ページ組み**（A4/A5 縦）:
- 上下左右に15mm以上の余白を確保し、ヘッダー（左=書名、右=章名）とページ番号は余白の中に収めます。
- 章扉は「第N章＋章タイトル」だけの独立ページで、ページ番号もヘッダーも付けません。本文ページには番号を付けます。
- POINT / NOTE / WARNING / COLUMN・図・表・コードブロックは、1ページに収まる限り途中で分割しません（ページより長いコード・表だけが分割されます）。

**初回のみ**: `python -m pip install markdown pygments python-docx pillow`（PDF・Wordの図には Chrome または Edge も必要）。
配色を変えたいときは `.claude/tools/book-format/book.css` 先頭の `--accent` 系の変数を編集して再実行してください。

## ④ YouTube台本の作り方

### /yt-structure — シリーズ構成

```
/yt-structure
```

大きなトピックを「ミニシリーズ（5〜8本）」に分割してプレイリストで束ねる設計です。

```
シリーズ全体
├── ミニシリーズ1「入門編」（7本）← プレイリスト①
├── ミニシリーズ2「基礎実践編」（6本）← プレイリスト②
└── ミニシリーズ3「応用編」（7本）← プレイリスト③
```

**1本 = 1コンセプト必須**: 複数のテーマをまとめず、1本で1つのことだけを教えます。

### /yt-list — 動画リスト

```
/yt-list         # 全体の動画リストを生成
/yt-list 1       # ミニシリーズ1だけを先に詳細化
```

各動画のタイムスタンプ設計・サムネイル訴求文・タイトル案・概要欄テキスト・ハッシュタグが生成されます。

### /yt-script — 台本執筆

```
/yt-script 5     # 動画05の台本を執筆
/yt-all          # 全台本を一括生成
/yt-all 1        # ミニシリーズ1だけを一括生成
```

**YouTube台本の特徴**:
- 会話文字数基準（解説: 750〜1,200字 / ハンズオン: 1,200〜1,800字）
- 2〜3分ごとの「パターン割り込み」で離脱防止
- CTA・エンドカード指示が自動挿入

### /yt-slides — スライド生成（.pptx）

```
/yt-slides 5     # 動画05のスライドを生成
/yt-slides-all   # 全動画のスライドを一括生成
/yt-slides-all 1 # ミニシリーズ1だけを一括生成
```

YouTubeスライドはUdemyとは異なる設計です:

| 項目 | Udemy | YouTube |
|-----|------|---------|
| テキスト量 | 箇条書き3点 | 1スライド15字以内 |
| デザイン | クリーン・情報量多め | インパクト重視 |
| 背景 | ライト系 | ダーク系グラデーション |
| アニメーション | シンプル | まとめのみビルドアニメーション |

生成されるスライドの種類:
- オープニングフック（動画で得られること）
- セクションタイトル（パートの切り替え）
- キーメッセージ（最重要概念を大きな文字で）
- 箇条書きまとめ（1点ずつフェードイン）
- コード表示（ハンズオン動画のみ）
- エンドカード（チャンネル登録・次動画）

### /yt-visuals — 視覚素材指示書

```
/yt-visuals 5    # 動画05の視覚素材指示書を生成
```

収録・編集時の作業指示書です。サムネイルデザイン・タイムライン別演出一覧・編集チェックリストが生成されます。

> **スライドとビジュアルの使い分け**:
> `/yt-slides` は実際に収録・編集に使う .pptx ファイルです。
> `/yt-visuals` は収録前後の作業メモとして使う指示書です。
> 両方を使う場合は `/yt-slides` → `/yt-visuals` の順で実行してください。

## よくある質問

**Q: コマンドが認識されない**
`.claude/commands/` フォルダがプロジェクトフォルダの直下にあるか確認してください。
正しい場所: `my-course-project/.claude/commands/plan.md`

**Q: 「concept.md が見つかりません」と言われた**
まず `/check` で進捗を確認してください。各コマンドは前フェーズのファイルが必要です。
正しい順序: `/plan` → `/structure` → `/toc` → `/script`

**Q: スクリプトが短すぎる（時間が足りない）**
生成後に「会話文字数（推定）」が表示されます。不足している場合は [WARNING] が表示されるので追記を依頼してください。
ファイル全体の文字数ではなく「鍵かっこ内の会話文字数」が基準です。

**Q: 途中で中断した**
生成のたびにファイルが保存されるため問題ありません。
`/check` で未生成を確認し、該当コマンドを実行すれば再開できます。

**Q: 3メディアを並行して進められる？**
はい。`/plan` の後はどのブランチコマンドから進めても構いません。

**Q: YouTubeで20分以上の動画を作りたい**
内容を複数本に分割することを強くお勧めします。`/yt-structure` の「1本 = 1コンセプト」の原則を参照してください。

**Q: YouTubeのスライドとビジュアル指示書の違いは？**
`/yt-slides` は収録・編集に使う実際の .pptx ファイルです。
`/yt-visuals` は収録前後に確認する作業指示書（Markdownファイル）です。
両方を使う場合は `/yt-slides` → `/yt-visuals` の順で実行してください。
