# メディア別スタイルガイド

---

## 共通ルール（全メディア）

### 禁止表現
| ❌ 書き言葉 | ✅ 話し言葉・読み言葉 |
|-----------|-----------------|
| 〜である | 〜です・〜ます |
| 〜における | 〜での |
| 上記の通り | さきほど説明した通り |
| 以下に示す | 以下のとおりです |
| 〜に他ならない | 〜なんです |

### 技術用語
- 初出時: カナ読みを併記（例: `Docker（ドッカー）`、`API（エーピーアイ）`）
- 略語初出: 正式名称を添える（例: `API（Application Programming Interface）`）
- コード・コマンド: バッククォートで囲む（例: `pip install`）

### コードブロック
- 必ず言語名を指定（❌ ` ``` ` → ✅ ` ```python `）
- 全コードにファイル名コメントを先頭に入れる（例: `# main.py`）
- 各行・ブロックに説明コメントを入れる

## Udemyスタイル

### 文体
- ですます調・口語体（「話しかける」形式）
- 1文: 40〜60字
- 「読む」より「聞いて理解できる」文章

### 必須パターン
1. **導入**: 前回振り返り（1文）+ 今回ゴール宣言（1文）
2. **3段階説明**: 概念定義 → 具体例・比喩 → 重要性（すべてのトピックに必須）
3. **まとめ**: 3点箇条書き + 各点に補足1文 + 次回橋渡し

### 話しかけパターン
| 場面 | 使う表現 |
|-----|---------|
| 導入 | 「みなさん、こんにちは！」 |
| 問いかけ | 「〜ですよね？」「〜したことありますか？」 |
| 難しい概念 | 「難しく感じるかもしれませんが、要するに〜」 |
| 確認 | 「ここまでついてきていますか？」（1レクチャー1回まで） |
| まとめ | 「今回は〜を学びました。整理すると：」 |
| 橋渡し | 「次のレクチャーでは〜を扱います。引き続きよろしく！」 |

## 書籍スタイル

### 文体
- ですます調・読書体（3メディア中もっとも丁寧）
- 1段落: 4〜6文・1文50字以内
- 一人称: 「本書では〜」「筆者は〜」

### 必須パターン
1. **章頭**: 「この章で学ぶこと」（3点）+ 前章との接続
2. **節頭**: 問題提起・背景・読者の疑問の言語化
3. **図解指示**: `[図X.X: タイトル | 種類: ○○ | 内容: ○○ | 自動生成: 可/要確認/手動]`
4. **章末**: 「本章のまとめ」（3点）+ 次章への橋渡し

## YouTubeスタイル

### 文体
- くだけた口語体（3メディア中もっともカジュアル）
- 1文: 20〜30字（テロップに収まる長さ）
- 体言止め・省略を積極的に活用

### 必須パターン
1. **冒頭30秒**: 視聴者の悩み/疑問を突くフック
2. **パターン割り込み**: 2〜3分ごとに「予告・転換・問題提起」で離脱防止
3. **CTA**: 高評価・チャンネル登録・コメント依頼（1動画1〜2回）
4. **エンドカード**: 次の動画カード + チャンネル登録ボタン（最後5秒）

### サムネイル訴求文の法則
- 20字以内
- 数字 / 疑問 / before-after のいずれかを使う
- 例: 「5分でわかるDocker入門」「なぜ失敗する？」「これだけ覚えればOK」

## メディア間での再利用ポイント

同じトピックを3メディアで扱う場合:

| 要素 | Udemy | 書籍 | YouTube |
|-----|------|------|---------|
| 説明の深さ | 中 | 深 | 浅〜中 |
| コード例 | 必要・詳細 | 必要・詳細 | 要点のみ |
| まとめ | 3点箇条書き | 章末まとめ | テロップ強調 |
| 次への誘導 | 次レクチャー | 次章 | 次動画 |
