# 書籍原稿の記法（/book-format のデザイン用）

`/book-format` は、原稿（Markdown）の書き方から **format-template/ のデザイン**（A4: `techbook-a4.html` + `style-a4.css` / A5: `techbook-a5.html` + `style-a5.css`）の部品を機械的に決めます。
AIが内容から推測して装飾を付けることはありません。**どの部品にしたいかは、原稿側で下のキーワードを使って明示してください。**

キーワードはすべて任意です。書かなければ、その部品が出ないだけで、本文は通常のデザインで出力されます。

---

## 1. 表紙・柱（ヘッダー）: `book/book_info.md`

書籍全体の情報は、プロジェクトの `book/book_info.md` に `# キーワード: 値` の形で1行ずつ書きます（コロンは省略して `# TITLE 書名` でも可）。
このファイルは `/book-structure` の実行時に `00_planning/concept.md` から自動で作られます（既にあれば上書きしません）。書名・サブタイトル・説明・特長は concept.md から写され、著者名・出版社名・シリーズ名・発行日は未記入で残るので、必要に応じて書き込んでください。
`[著者名]` のように角かっこで囲んだ値は「未記入」とみなして表紙に出しません。

```markdown
# SERIES: 実践AIエージェント開発シリーズ 01
# SUBTITLE: LLM・ツール・ループの基本から実装まで
# TITLE: Claude Codeではじめる
# TITLE: **AIエージェント開発**
# TITLE: 実践入門
# DESCRIPTION: エージェントの仕組みの理解から、
# DESCRIPTION: 最初のエージェントづくりまでをこの1冊で。
# FEATURE: LLM・ツール・ループの3要素で仕組みをスッキリ理解
# FEATURE: 「POINT」「NOTE」「WARNING」で重要度がひと目でわかる
# AUTHOR: 山田太郎 著
# PUBLISHER: TECH PRESS BOOKS
# DATE: 2026年10月
# HEADER: Claude Codeではじめる AIエージェント開発 実践入門
```

| キーワード | 表示される場所（テンプレートの部品） | 複数行 |
|----------|------------------------------|------|
| `TITLE` | 表紙の書名（`.cover-main-title`）。行ごとに改行。`**…**` の部分は強調色（`.highlight`） | 可 |
| `SUBTITLE` | 表紙の書名の上のキャッチ（`.cover-subtitle`）。行ごとに改行 | 可 |
| `SERIES` | 表紙左上のシリーズ名バッジ（`.cover-series-badge`） | — |
| `DESCRIPTION` | 書名の下の説明文（`.cover-desc`）。行ごとに改行 | 可 |
| `FEATURE` | 表紙中央の特長リスト（`.cover-feature-item`、先頭に ✔） | 可 |
| `AUTHOR` | 表紙下部の著者欄（`.cover-author`）。行ごとに改行（所属と氏名を分けるときなど） | 可 |
| `DATE` | 表紙下部の著者欄の日付（`.cover-date`） | — |
| `PUBLISHER` | 表紙右下の出版社名（`.cover-publisher`） | — |
| `HEADER` | 本文ページ左上の柱（ヘッダー）の書名。省略時は TITLE をつなげたもの | — |

優先順位: `/book-format` の引数（`title="…"` など） ＞ `book_info.md` ＞ `00_planning/concept.md`（メインタイトル・サブタイトル）。

複数行の `SUBTITLE`・`AUTHOR` は、PDFのしおり・Markdownのフロントマター・Word版では半角スペースでつないだ1行になる（表紙の改行は HTML/PDF のみ）。

## 2. 章扉（章ごとの最初のページ）

```markdown
# 第1章: AIエージェントとは何か
# EN-TITLE: WHAT IS AN AI AGENT
# TAGS: LLM, トークン, ツール呼び出し, エージェンティックループ

## この章の概要

（任意）この章の概要の文章。

> [!DIALOGUE]
> **生徒**: 先生、Webサイトのデータって自分のPCにあるわけじゃないんですね？
> **先生**: その通り！ 次のページから詳しく見ていこう。

## この章で学ぶこと

本章では以下を学びます：

- 学習目標1
- 学習目標2

前章では〜を学びました。本章では〜を扱います。
```

| 書き方 | 章扉での表示 |
|------|-----------|
| `# 第N章: タイトル`（1行目・必須） | 「第N章」バッジ（`.divider-badge-chap`）＋ 章タイトル（`.divider-title`）。右ページの柱にも章タイトルが出る。`# はじめに` のように「第N章」が無い章はバッジなし |
| `# EN-TITLE: 英字` | 「CHAPTER 01 · 英字」の英字ラベル（`.divider-badge-en`）。書かなければ英字ラベルは出さない |
| `# TAGS: 語1, 語2` | キーワードタグ（`.concept-tag`、「#語1」の形）。区切りは `,` `、` または `#語1 #語2` |
| 章見出しと最初の `##` の間の文章 | 概要の枠（`.divider-lead-box`） |
| `## この章の概要`（または「本章の概要」） | 見出し付きの概要の枠（`.divider-lead-box` ＋「● この章の概要」） |
| `## この章で学ぶこと` | 学習ゴールの枠（`.divider-goals-card`）。最初の箇条書きの各項目に ✔。**箇条書きより後の文章**（前章との接続など）は、その下の概要の枠に入る |
| `> [!DIALOGUE]` の会話 | 会話ボックス（`.dialogue-box`）。章扉以外（本文中）でも使える |

- `# EN-TITLE:` `# TAGS:` の行は**章見出しの直後**に書く。本文には出力されない（メタ情報）。
- 章扉に入るのは、章の先頭から「この章の概要」「この章で学ぶこと」までの部分。最初の番号付きの節（`## 1.1 …`）からが本文ページ。

## 3. 本文の見出し

| 書き方 | 表示 |
|------|-----|
| `## 1.1 節タイトル` | 節見出し（`.sec-h2`）。先頭の番号「1.1」は青いバッジ（`.sec-h2-badge`）になる。目次にも載る |
| `### 小見出し` | 小見出し（`.sub-h3`、左に青い線） |
| `#### 小小見出し` | 4階層目（■付き） |
| `## COLUMN: タイトル`（`## コラム: タイトル` も可） | 節全体がコラム枠（`.box-column`、点線枠 + COLUMN タグ）。長いコラムはページをまたげる |
| `## 本章のまとめ` | 節見出し + まとめ枠。最初の箇条書きが枠（各項目に ✔）に入り、その後の文章（次章への橋渡し）は通常の本文 |
| `---` | 節の区切り（節の直前の `---` は表示しない） |

## 4. 囲み記事（引用ブロックの先頭ラベルで決まる）

```markdown
> **POINT**: 見出しなしの本文。

> **POINT: ここだけは覚える！**
> 見出し付き。見出しの次の行からが本文です。

> **NOTE**: 補足です。
> **WARNING**: 注意です。
```

| 種別（テンプレートの部品） | ラベル（大文字小文字・英日どちらも可） |
|------------------------|--------------------------------|
| POINT（黄: `.box-point`） | ポイント / 重要 / 要点 / POINT / IMPORTANT |
| NOTE（青: `.box-note`） | 補足 / メモ / 参考 / 用語 / 具体例 / 例 / 注 / NOTE / INFO |
| WARNING（赤: `.box-warning`） | 注意 / 注意点 / よくある誤解 / WARNING / CAUTION |
| COLUMN（点線: `.box-column`） | コラム / 豆知識 / 余談 / COLUMN |
| TIP（緑・追加部品） | ヒント / コツ / TIP / TIPS |
| DANGER（濃い赤・追加部品） | 警告 / 危険 / DANGER |

- 書き方は `> **ラベル**: 本文` / `> **ラベル: 見出し**`（次の行から本文）/ `> NOTE: 本文`（太字なしはラベル完全一致のみ）/ `> [!TIP]` のいずれか。
- **ラベルのない引用**（`> 文章` だけ）は、内容から種別を推測せず、通常の引用（灰色の線）として表示する。

### ステップカード（手順）

```markdown
> **STEP 1**: HTMLファイルを作成して基本構造を記述する
> テキストエディタを開き、拡張子「`.html`」で保存します。

> **STEP 2**: CSSで文字の色やフォントサイズを指定する
```

`**STEP 番号**: 見出し` の次の行が説明文（任意）になる（`.step-card` / `.step-badge`）。「ステップ1」も可。

### 会話ボックス

```markdown
> [!DIALOGUE]
> **生徒**: 質問の文章。
> **先生**: 答えの文章。
> 行頭に名前がない行は、直前の発言の続きになります。
```

- `**名前**:` で発言を区切る（`[!会話]` も可）。
- バッジの色: 先生・講師・筆者・著者・先輩など → 青（`.avatar-teacher`）、生徒・読者・受講者・初心者など → オレンジ（`.avatar-student`）。それ以外の名前は登場順にオレンジ → 青。

## 5. 図・表・コード

| 書き方 | 表示 |
|------|-----|
| `[FIG_X_Y｜種類｜自動生成フラグ｜タイトル｜内容の要点]` | 図の枠（`.doc-figure` / `.figure-frame`）＋「図X.Y: タイトル」のキャプション。`book/05_figures/chapter_XX/fig_X_Y.svg`（または .png）があれば取り込み、無ければ点線の「入稿待ち」の枠 |
| Markdown の表 | 見出し行が青い表（`.tech-table`） |
| ` ```python ` のコードブロック | 暗い背景のコード枠（`.code-container`）。上部に言語名（`.file-tag`）とファイル名（1行目のコメント `# main.py` から自動検出） |
| ` ```text ` / 言語なし | 上部の帯なしのコード枠（プロンプト例など） |
| `` `インラインコード` `` / `**強調**` | 背景付きの等幅文字 / 濃い青の太字 |

- 「次のコードを保存します。」のような直前の短い段落は、コード・表・図と同じページに置かれる。
