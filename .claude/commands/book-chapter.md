## 図マーカーの書き方（重要）

本文中に図が必要な箇所は以下のフォーマットで挿入する。
`/book-figures`・`/book-embed` コマンドがこの情報をもとに図を処理する。

**重要な設計原則**:
- マーカーの1トークン目（`FIG_X_Y`）は、そのまま図ファイル名の元になる（`fig_X_Y.svg`等）。**Windowsのファイル名で使えない文字（`\ / : * ? " < > |` の半角記号）を含めないこと。**
- 区切り記号には全角の `｜`（U+FF5C）を使う。半角の `|`（パイプ）や半角コロン `:` は、Windowsのファイル名で予約された文字のため使用しない。
- 内容欄は「何を描くかの要点」を1文・30字程度で簡潔に書く。詳細な構図説明は`/book-figures`が生成する`fig_X_Y_prompt.md`側に書けばよく、本文マーカーに長々と書き込む必要はない。

```
[FIG_X_Y｜種類｜自動生成フラグ｜タイトル｜内容の要点]
```

- `種類`: 概念図/フロー/構造図/比較/スクリーンショット/イラスト のいずれか
- `自動生成フラグ`: 可（そのまま自動生成可）/ 要（要確認）/ 手（手動作成・撮影が必要）
- `X`は章番号、`Y`はその章内の通し番号（例: 第2章の3番目の図なら`FIG_2_3`）

**記述例**:
```
[FIG_2_3｜概念図｜可｜Dockerのアーキテクチャ｜Container→Engine→Host OSの3層構造]

[FIG_5_2｜スクリーンショット｜手｜設定画面｜Difyのモデルプロバイダー設定画面]

[FIG_1_1｜イラスト｜要｜AIエージェントの比喩｜地図を持ち迷路を進むロボット]
```

表示用のキャプション（「図2.3: Dockerのアーキテクチャ」のような形式）は、`FIG_X_Y`のXとYをピリオドで繋いで機械的に生成できる（`/book-embed`が処理する）。本文中でマーカー以外の場所からその図に言及する際は、この「図X.Y」形式を使ってよい（例:「詳しくは図2.3を参照」）。

各章には、内容の理解を助ける図を**最低3〜4点**は配置することを目安にする。概念の説明・比較・フロー・アーキテクチャ図解など、文章だけでは伝わりにくい箇所には積極的にマーカーを挿入すること。

## デザイン用の記法（/book-format で使われる）

`/book-format` は原稿の書き方から format-template/ のデザイン部品（章扉・POINT/NOTE/WARNING/COLUMN・ステップカード・会話ボックスなど）を機械的に決める。
**記法の全体は `references/book-markup.md` を Read ツールで読んでから執筆すること。** 要点:

- 章見出しの直後に `# EN-TITLE: 英字の章ラベル` と `# TAGS: キーワード1, キーワード2, キーワード3`（章扉に表示。3〜5語）を書く
- 囲み記事は必ず先頭にラベルを付ける（`> **POINT**: …` / `> **NOTE**: …` / `> **WARNING**: …`）。見出しを付けるときは `> **POINT: 見出し**` とし、本文は次の行から
- 手順は `> **STEP 1**: 見出し`（次の行に説明）、対話形式の導入は `> [!DIALOGUE]` + `> **生徒**: …` / `> **先生**: …`
- コラムの節見出しは `## COLUMN: タイトル`（または `## コラム: タイトル`）
- 節見出しは `## X.1 タイトル` のように番号を付ける（番号がバッジになる）

## 章本文テンプレート

```markdown
# 第X章: [タイトル]
# EN-TITLE: [章の英字ラベル（例: INTRODUCTION）]
# TAGS: [キーワード1], [キーワード2], [キーワード3]

## この章で学ぶこと

本章では以下を学びます：

- [学習目標1（〜できるようになる）]
- [学習目標2]
- [学習目標3]

前章では [前章の要点を1文で] を学びました。
本章では、それを踏まえて [本章のテーマへの接続] を扱います。

---

## X.1 [節タイトル]

[導入文。この節で扱う問題・背景・読者の疑問を言語化する]

### [小見出し]

[説明文。以下の順で書く]
1. [概念定義: 〜とは、〜である]
2. [具体例: 「たとえば〜」]
3. [重要性: 「これを理解すると〜のときに役立つ」]

[FIG_X_Y｜種類｜自動生成フラグ｜タイトル｜内容の要点]

```[言語]
# ファイル名: xxx.py
[コード（各行にコメント付き）]
```

> **POINT**: [重要な注意点・よくある誤解の訂正]

> **STEP 1**: [手順の見出し]（手順を示す場合）
> [手順の説明]

[まとめの一文。次の節への橋渡し]

---

## X.2 [節タイトル]

（同形式で繰り返し）

---

## COLUMN: [タイトル]（コラムがある場合）

[本文からやや外れた補足情報・実務での応用例・豆知識]

---

## 本章のまとめ

本章で学んだことを整理します：

- [要点1]
- [要点2]
- [要点3]

次章では **[次章のタイトル]** を扱います。[次章への期待感を高める一文]
```

## 書籍文体ルール

- **文体**: ですます調・読書体（Udemy/YouTubeより丁寧）
- **段落**: 4〜6文・1文50字以内
- **一人称**: 「本書では〜」「筆者は〜」
- **コード**: 全コードにファイル名コメント（例: `# main.py`）
