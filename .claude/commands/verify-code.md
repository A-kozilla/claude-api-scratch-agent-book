# /verify-code — コード実行検証

コンテンツ内のコードブロックを実際に実行し、動作確認・バグ検出を行います。
「動くコードサンプル」を保証することで受講者・読者の信頼を高めます。

引数 `$ARGUMENTS`:
- `udemy 1 2` → Section 01, Lecture 02 のコードを検証
- `book 3` → 第3章のコードを検証
- 引数なし → 全コードブロックを対象に検証

---

## 対象となるコードブロック

```python  # → 実行検証対象
```bash    # → 実行検証対象
```javascript # → 実行検証対象（Node.js環境）
```sql     # → 構文チェックのみ
```yaml    # → 構文チェックのみ
```json    # → 構文チェックのみ

---

## 処理手順

### Step 1: コードブロックの抽出

対象ファイルからすべてのコードブロックを抽出する。
各ブロックに番号を振り、言語・行数・前後の文脈（何を実行するコードか）を記録する。

### Step 2: 実行環境の確認

```bash
# 利用可能な実行環境を確認
python3 --version
node --version
bash --version
```

### Step 3: コードの実行検証

各コードブロックについて以下を実行する:

**Pythonコードの場合**:
```bash
# 一時ファイルに保存して実行
cat > /tmp/verify_code.py << 'EOF'
[抽出したPythonコード]
EOF

# 必要なパッケージのインストール（import文から自動検出）
pip install [検出したパッケージ] --break-system-packages -q 2>&1

# 実行（タイムアウト30秒）
timeout 30 python3 /tmp/verify_code.py 2>&1
EXIT_CODE=$?
```

**Bashコードの場合**:
```bash
# 危険なコマンドを含まないか確認してから実行
# rm -rf / sudo rm などの破壊的コマンドは実行しない
timeout 30 bash /tmp/verify_code.sh 2>&1
```

**実行できないコードの扱い**:
- 外部APIキーが必要なコード → 構文チェックのみ実施
- ファイルシステム依存のコード → 仮想環境でモック実行
- GUIを必要とするコード → 構文チェックのみ実施

### Step 4: 結果の分類

| 判定 | 意味 |
|-----|------|
| ✅ 動作確認済み | 実行して期待通りの出力が得られた |
| ⚠️ 要確認 | 実行できたが出力が想定と異なる、または実行環境に依存 |
| ❌ エラー | 実行してエラーが発生した |
| 🔍 構文チェックのみ | 実行環境がないため構文のみ確認 |

### Step 5: レポートの生成

```markdown
# コード検証レポート

対象ファイル: [ファイルパス]
検証日: YYYY-MM-DD
コードブロック数: X個
  ✅ 動作確認済み: X個
  ⚠️ 要確認: X個
  ❌ エラーあり: X個
  🔍 構文チェックのみ: X個

---

---

## 注意事項

> ⚠️ **検証の限界**
>
> - 外部サービス（OpenAI API・Dify・Dockerなど）への接続が必要なコードは完全検証不可
> - 環境依存のコード（OSのパス・GPUの有無など）はローカル環境で別途確認が必要
> - このコマンドで「動作確認済み」になったコードも、受講者の環境では動かない場合があります
>
> **公開前に実際の学習環境（受講者と同じ環境）での動作確認を必ず行ってください。**
