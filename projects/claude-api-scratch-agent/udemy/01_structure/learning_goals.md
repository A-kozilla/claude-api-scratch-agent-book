# 学習目標: Claude APIでスクラッチから作るAIエージェント開発入門

| Section | 理解できる | 実行できる | 応用できる |
|---|---|---|---|
| 00 コース概要 | SDKやフレームワークを使わずに作る意義と、コース全体の流れ | 学習計画とAPI利用料の目安を立てる | 自分の目的に合わせて重点セクションを選ぶ |
| 01 AIエージェントとは | LLM＋ツール＋ループという構造、チャットボットとの違い、コンテキストウィンドウの上限 | エージェンティックループの流れを図で説明する | 業務課題がエージェント向きかどうかを見極める |
| 02 開発環境 | Claude API・Console・APIキー・利用上限の関係 | uvでプロジェクトを作り、`.env`でキーを管理し、curlとhttpxでAPIを呼ぶ | 新しいプロジェクトでも同じ環境を再現する |
| 03 Messages API | ヘッダー・ボディ・content配列・stop_reason・usage・エラー型、APIがステートレスであること | 会話履歴を自分で管理するCLIチャットを作る | エラーレスポンスから原因を特定し、古い仕様のコードを現行仕様に直す |
| 04 自作クライアント | リトライすべきエラーとすべきでないエラー、SSEのイベント構造 | `llm_client.py`（関数化・例外・リトライ・ストリーミング・コスト計測）を実装する | レート制限やタイムアウトに強いクライアントに調整する |
| 05 最初のエージェント | ツールを実行するのはClaudeではなく自分のコードであること、tool_use／tool_resultの対応 | JSON Schemaでツールを定義し、エージェンティックループを実装する | 自分の業務用ツールを追加してエージェントを拡張する |
| 06 ツール設計 | 良いツールの命名・説明・粒度、並列呼び出し、`is_error`、構造化出力、サーバーツールとの違い | ツールレジストリ・安全なファイル操作ツール・構造化出力を実装する | 権限と確認フローを含めた実務用ツール群を設計する |
| 07 コンテキスト管理 | トークン予算、圧縮・キャッシュ・長期メモリの役割、thinkingとeffort | count_tokens・履歴圧縮・Prompt caching・ファイルメモリを実装する | 長時間動くエージェントのコストと品質のバランスを設計する |
| 08 マルチエージェント | コンテキストを分離する意義、サブエージェント＝子ループという構造 | サブエージェントをツールとして実装し、asyncioで並列実行する | 役割・モデル・ツール権限を分けたエージェント構成を設計する |
| 09 設計パターン | 単一呼び出し／ワークフロー／エージェントの判断基準、5つの代表パターン | チェーン・ルーティング・並列化・評価者-最適化者を実装する | 課題に応じて最もシンプルなパターンを選び、組み合わせる |
| 10 実践プロジェクト | 業務自動化マルチエージェントの全体設計 | オーケストレーター＋専門エージェントを実装し、モックでテストし、コストを計測する | 自分の業務に合わせて役割やツールを置き換える |
| 11 本番運用・まとめ | プロンプトインジェクション、ガードレール、eval、監視、Batch API | 入出力ガードレールと簡易evalを実装する | 実務導入のチェックリストに沿って運用計画を立てる |
