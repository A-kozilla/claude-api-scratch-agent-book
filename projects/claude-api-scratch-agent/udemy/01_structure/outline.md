## 設計上の意図

- **完全スクラッチ**: SDK・フレームワーク・Claude Code は使わない。Section 02でcurl→httpxの順に「生のHTTP」を体験させ、Section 03〜04でフレームワークが隠している処理（履歴管理・エラー処理・リトライ・SSEパース）を自分で書く。
- **1つのコードベースを育てる**: Section 04で作る `llm_client.py` を以降の全セクションで import して使い、`agent.py`（Section 05）→ ツールレジストリ（06）→ コンテキスト管理（07）→ サブエージェント（08）→ パターン（09）→ 実践プロジェクト（10）と拡張する。
- **段階設計**: Section 01〜04で基礎（概念・環境・API・クライアント）、05〜07で単一エージェント、08〜09でマルチエージェント、10で統合、11で運用という順序にし、[[target_audience]]の「いきなりマルチエージェントで挫折」を防ぐ。
- **ステートレス性の体感**: `01-03`でコンテキストウィンドウの概念を先出しし、`03-04`で履歴を自分で積み直す実装、`07-01〜02`でトークン計測と圧縮へと3段階で深める。
- **現行API仕様への準拠**: `anthropic-version: 2026-10-21`、`temperature` 等の廃止、prefill不可、強制 `tool_choice` 不可、adaptive thinking と `effort` など、古い記事との差分でつまずかないよう `03-01`・`03-03`・`03-05`で明示する。
- **限界への言及**: `01-04`（限界の先出し）・`08-01`（単一エージェントの限界）・`09-01`（エージェントを使わない判断）・`11-01〜03`（安全性・評価・コスト）で過剰な期待に手当てする。
- 書籍との対応: Section 01〜10 ≒ 第1〜10章、Section 11 ≒ 第11章（本番運用）＋第12章（まとめ）。
