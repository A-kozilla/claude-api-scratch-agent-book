# 章間接続マップ: Claude APIでスクラッチから作るAIエージェント開発入門

各章について「前章から持ち込む知識 → 本章で得る知識 → 次章への橋渡し」を整理する。

---

## はじめに
- **前章から持ち込む知識**: なし
- **本章で得る知識**: 本書の目的（SDKなしで仕組みから作る）・対象読者・前提知識・扱わないもの・読み方
- **次章への橋渡し**: 「まずは、これから作る“AIエージェント”とは何かを正確に定義するところから始めます」

## 第1章: AIエージェントとは何か
- **前章から持ち込む知識**: 本書全体の目的意識
- **本章で得る知識**: エージェント＝LLM＋ツール＋ループ、チャットボットとの違い、APIのステートレス性とコンテキストウィンドウ、活用事例と限界
- **次章への橋渡し**: 「この構造を自分の手で作るために、まずはClaude APIを呼べる開発環境を整えましょう」

## 第2章: 開発環境を整える
- **前章から持ち込む知識**: エージェントの基本構造
- **本章で得る知識**: Console・APIキー・利用上限、uv＋VS Code＋httpx の環境、`.env` によるキー管理、curl と httpx での初回リクエスト
- **次章への橋渡し**: 「リクエストが通ったら、次はその中身——ヘッダー・ボディ・レスポンスの一つひとつ——を読み解きます」

## 第3章: Messages APIを理解する
- **前章から持ち込む知識**: 最初のリクエストを送れる環境
- **本章で得る知識**: リクエスト／レスポンスの全構造、stop_reason と usage、system とパラメータ、会話履歴を自分で管理する実装、エラー型
- **次章への橋渡し**: 「毎回同じコードを書かずに済むよう、そして失敗に強くなるよう、自分だけのAPIクライアントにまとめましょう」

## 第4章: 自作APIクライアントを作る
- **前章から持ち込む知識**: Messages API の仕様とエラー型
- **本章で得る知識**: `llm_client.py`（関数化・例外・リトライ・SSEストリーミング・ログ・コスト計測）
- **次章への橋渡し**: 「土台ができました。いよいよツールとループを加えて、最初のエージェントを作ります」

## 第5章: 最初のAIエージェントを作る
- **前章から持ち込む知識**: `llm_client.py`、content配列と stop_reason の扱い
- **本章で得る知識**: ツール定義（JSON Schema）、tool_use／tool_result の往復、エージェンティックループ（`agent.py`）
- **次章への橋渡し**: 「1つのツールで動いたら、次は複数ツール・エラー・安全性を備えた実務レベルの設計へ進みます」

## 第6章: ツールを実務レベルで設計する
- **前章から持ち込む知識**: エージェンティックループ
- **本章で得る知識**: ツール設計原則、ツールレジストリ、並列呼び出しと is_error、安全なファイル操作、構造化出力、サーバーツールの位置づけ
- **次章への橋渡し**: 「ツールを使って長く動くほど履歴は膨らみます。次はコンテキストとメモリの管理に取り組みます」

## 第7章: コンテキストとメモリを管理する
- **前章から持ち込む知識**: 複数ツールを持つエージェント、usage の読み方

- **次章への橋渡し**: 「1つのエージェントで抱えきれないときは、コンテキストを分けて複数のエージェントに任せます」

## 第8章: マルチエージェントを自作する

- **次章への橋渡し**: 「部品がそろったところで、どんな形に組み立てるべきか——設計パターンと判断基準を整理します」
