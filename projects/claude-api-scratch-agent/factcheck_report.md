## 優先対処リスト（❌ 要修正）

5件すべて、2026-11-08 に原稿を修正済み:

1. **chapter_02.md L91〜98（STEP 1・STEP 3）** — 現行の Console では、キー作成時のワークスペース指定が任意になっている。ワークスペースに紐づけないキーは毎回 `anthropic-workspace-id` ヘッダーが必要で、ないと400（"This API key is not scoped to a workspace…"）になる。STEP 1 を「任意」として飛ばした読者は、本書の全リクエストが400になる。
   → 修正案: STEP 3 を「ワークスペースは STEP 1 で作ったもの（作らなかった場合は Default Workspace）を**必ず選ぶ**。選ばないと `anthropic-workspace-id` ヘッダーが必要になり、本書の手順では400になる」に変える。2.5節のトラブル表にも同じエラーの行を足す。

2. **chapter_06.md L549付近（6.2版 agent.py の `execute_tool_uses`）【コード】** — `except ToolError` しかないため、天気ツールの `ValueError`（未知の都市）や httpx の接続エラーでプログラムが落ちる（偽APIで再現）。L664「第5章とまったく同じ振る舞いです」とも食い違う。
   → 修正案: `except Exception as e:` の分岐を足し、`logger.warning(...)` を出したうえで `make_tool_result(tool_use["id"], f"エラー: {type(e).__name__}: {e}", is_error=True)` を返す（修正版で落ちなくなることを確認済み）。

3. **chapter_07.md L1107〜1116（実行ログ例と説明）** — 2回目の呼び出しのログが `in=1207 cache_write=0` になっている。しかしこのコードはトップレベルの自動キャッシュ（L1056）を使っており、毎回、新しく足された末尾がキャッシュに書き込まれる。そのため `input_tokens` は小さい値になり、cache_write も0にはならない。第8章の例とも矛盾する。
   → 修正案: ログを `in=6 … cache_write=3564 cache_read=0 cost=$0.0198` と `in=6 … cache_write=1353 cache_read=3564 cost=$0.0117` のような形にする。「`input_tokens` はキャッシュされていない部分」の説明も、末尾が毎回書き込まれる旨に改める（文案は chapter_07_factcheck.md にある）。

4. **chapter_08.md L848（summary 出力例）** — `cache_write=0 cache_read=0` は、同章 L481〜483 の「Haiku は短いプロンプトもキャッシュされる」と矛盾する。
   → 修正案: `calls=11 input=92 output=2,310 cache_write=11,400 cache_read=13,500 total=$0.0382` のような値に差し替える。

5. **chapter_08.md L1262〜1263・L1267（逐次と並列の比較例）** — 同じく cache=0 になっている。公式ドキュメントでは、キャッシュは最初の応答が始まってから使えるようになる。そのため並列実行では、逐次実行よりキャッシュの読み取りが少なくなるのが正しい。
   → 修正案: 例の数値と L1267 の説明を差し替える（文案は chapter_08_factcheck.md にある）。

> 3〜5 は同じ原因の不整合（自動キャッシュ付きの呼び出しなのにキャッシュ値が0）。実APIで1回実行し、実測値に差し替えるのが確実。
